# Verification of Section 3 recommendations

Checked October 14, 2026. This is supporting research, outside the two-page executive summary and the upload package. Findings concern the reviewed documentation for `microsoft/Florence-2-base`; they are not a claim that no Microsoft page anywhere discusses these subjects.

The pinned README at revision `5ca5edf5bd017b9919c05d08aebef5e4c7ac3bac` matches the current model-card README byte for byte. Download hashes and the other repository revisions are recorded in [documentation-check.json](sources/documentation-check.json).

| Recommendation | What Microsoft already provides | Remaining gap and decision |
| --- | --- | --- |
| OCR transcription accuracy and recall | The card reports captioning CIDEr, detection mAP, grounding Recall@1 and referring-expression accuracy/mIoU. Fine-tuned checkpoints also have VQA accuracy. The technical report and notebook include qualitative OCR examples. | No character error rate, word error rate or OCR text-region recall benchmark was found in the reviewed sources. Retain the recommendation, explicitly for Florence-2-base. Scores for other tasks or checkpoints do not supply this evidence. |
| Language and script coverage | General training-data provenance, semantic/spatial coverage statistics and examples are available. The paper cites multilingual work in its related literature. | No evaluated OCR language/script inventory or per-language/script transcription scores were found. Retain the recommendation. This absence does not demonstrate that any particular language is unsupported. |
| Uncertainty, omissions and use limits | The paper describes confidence thresholding to filter training annotations. The card and notebook show `max_new_tokens=1024`; Microsoft's separate tutorial discusses a 1,024-token limit and a segmentation limitation/workaround. OCR output formats and examples are documented. | This is partial overlap. Refocus the recommendation on recognizing incomplete or unreliable OCR, evidence about OCR failure conditions, guidance on verification, and calibration evidence for any proposed output confidence scores. Do not claim that generation limits or confidence are wholly undocumented. |

## Primary sources reviewed

- [Florence-2-base model card, pinned revision](https://huggingface.co/microsoft/Florence-2-base/blob/5ca5edf5bd017b9919c05d08aebef5e4c7ac3bac/README.md): Model Summary, generation examples, Tasks/OCR output formats, and both benchmark tables. The fine-tuned rows describe separate checkpoints.
- [Linked technical report, arXiv v1](https://arxiv.org/html/2311.06242v1): training annotations and filtering in Sections 4.1–4.3; dataset statistics in Section 5; evaluations in Section 6; OCR fine-tuning data in Appendix B/Table 14; qualitative OCR examples in Appendix E.5/Figure 15. Annotation-filtering confidence is not a calibrated measure of correctness for a new transcription.
- [Published CVPR 2024 paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Xiao_Florence-2_Advancing_a_Unified_Representation_for_a_Variety_of_Vision_CVPR_2024_paper.pdf) and [supplement](https://openaccess.thecvf.com/content/CVPR2024/supplemental/Xiao_Florence-2_Advancing_a_CVPR_2024_supplemental.pdf): checked the published version as well as the linked preprint. The supplement is image-based; its pages were reviewed visually, with relevant data-analysis, experiment and OCR pages enlarged. Supplement Section G.5/Figure 11 shows OCR predictions, not a scored multilingual OCR benchmark.
- [Microsoft's linked Florence-2-large inference notebook](https://huggingface.co/microsoft/Florence-2-large/blob/21a599d414c4d928c9032694c424fb94458e3594/sample_inference.ipynb): inspected cell sources and text outputs, including the prediction function and OCR section. It demonstrates the large checkpoint and cannot establish base-checkpoint accuracy. OCR examples return text or text with quadrilateral coordinates; no calibrated OCR confidence field is explained.
- [Florence-2-base processing code](https://huggingface.co/microsoft/Florence-2-base/blob/5ca5edf5bd017b9919c05d08aebef5e4c7ac3bac/processing_florence2.py): `parse_ocr_from_text_and_spans`, the OCR branch of `post_process_generation`, and score-related branches. Score machinery for other parsing tasks does not establish calibrated transcription confidence.
- [Microsoft's additional Florence-2 tutorial repository](https://github.com/microsoft/dstoolkit-finetuning-florence-2/tree/5f653d917c793a7d85f2e6141c0abff01d587c44): README and both notebooks. `01-Base_Model.ipynb` explains the token limit, OCR examples and segmentation limitations; its model-loading cell selects `microsoft/Florence-2-large-ft`, despite the notebook's title. Its examples are not base-model benchmarks. `02-Object_Detection_Finetuning.ipynb` concerns object detection rather than OCR evaluation. Neither notebook supplies the missing language-by-language OCR evidence or calibration guidance.

## Distinguishing other Microsoft products

Microsoft does publish [OCR capabilities and limitations guidance for Azure Vision](https://learn.microsoft.com/en-us/azure/ai-foundry/responsible-ai/computer-vision/ocr-characteristics-and-limitations?context=%2Fazure%2Fcognitive-services%2Fcomputer-vision%2Fcontext%2Fcontext), including word error rate, service confidence scores and missed-text considerations. That page documents a managed OCR service, not the Florence-2-base checkpoint. The report's use of an Azure OCR service to create training labels does not transfer the service's measured accuracy, language support or confidence semantics to Florence-2. Such guidance could inform a Florence-specific documentation section once Microsoft validates its applicability.

## Resulting report changes

The critique now acknowledges existing recall/accuracy metrics, qualitative OCR examples, generation settings and training-annotation confidence thresholds. Section 3 retains three brief recommendations, each with the evidence required and who could provide it, as Question 3 requests. The third recommendation builds on existing examples instead of implying that token limits have never been documented. No inference experiment was conducted and no missing performance figures were invented.
